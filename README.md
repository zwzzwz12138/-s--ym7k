微信支付分账与合规架构——避免“二清”风险的技术方案
SaaS餐饮外卖平台的支付架构设计涉及一个不可回避的合规红线——“二清”。理解二清的定义、风险以及合规的解决方案，是搭建平台型餐饮SaaS系统的前提条件。

二清是指平台方在未取得支付牌照的情况下，先代收用户资金到平台账户，再将资金分发给入驻商户的行为。具体流程为：用户付款→资金到平台方商户号→平台方再分发给二级商户。平台在中间做了一次“清算”，这就是所谓的“二次清算”。这种模式触犯了两个核心合规问题：一是无证经营支付业务，资金清算属于支付牌照许可范围；二是资金池风险，资金在平台账户停留期间存在被挪用、卷款跑路的风险。微信支付的风控系统对资金流向有完整的监控链路，当商户号出现“收多转少”的规律性资金流出、频繁向多个不同账户转账等特征时，会触发风控管控。

合规的解决方案是使用微信支付的“服务商分账”能力，该模式的核心逻辑是：用户的付款通过微信支付的合规分账能力，在支付完成的同时自动按预设规则将资金分配到各收款方，平台方不经手资金。具体技术流程为：平台作为服务商，为每个入驻商户创建特约商户号，商户必须独立进件、绑定唯一主体资质与结算账户。用户下单支付时，资金直接进入商户的微信支付账户，平台通过分账接口按预设比例将平台佣金部分分账到平台账户。分账比例的限制是技术实现中需要特别注意的约束，微信原生分账模式下，单笔订单最多可将30%资金分给第三方商户或合作方。
